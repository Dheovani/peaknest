# Local development runbook

Use Node 24+, Corepack, pnpm 11.27.0, Docker Compose, and the root `.env.example`. Copy it to `.env`, replace the placeholder auth secret with at least 32 random characters, run `docker compose up -d postgres`, then `pnpm db:migrate`. On Windows PowerShell, use `pnpm.cmd` when script execution policy blocks `pnpm.ps1`. Run `pnpm dev:web` for Next.js and open `/login`; create a personal account at `/register`, then sign in and out through `/account`. The migration creates only Better Auth identity/session tables, with no seeded users. `pnpm dev:mobile` starts Expo but mobile login is not part of this slice. `pnpm dev` starts both in Turbo.

The identity migration is additive. If deployment fails before application traffic reaches it, restore from the database backup or apply a reviewed rollback that drops the four new auth tables in foreign-key order. Do not drop these tables once real accounts exist. Better Auth's in-memory login rate limiter is suitable for local development and a single server instance; production with multiple instances needs shared rate-limit storage before launch.

For integration tests, create a disposable database and set `TEST_DATABASE_URL` to its PostgreSQL URL. Use `127.0.0.1` for local Docker port forwarding on Windows to avoid `localhost` resolving to an unavailable IPv6 listener. For Playwright, install Chromium with `pnpm exec playwright install chromium` and run `pnpm test:e2e:web`. For Maestro, install its CLI, boot an Android emulator or iOS simulator, start Metro with `pnpm dev:mobile`, build/install the app with `pnpm --filter @fitness/mobile exec expo run:android --no-bundler` or `expo run:ios --no-bundler`, and run `pnpm test:e2e:mobile`. The app ID is `com.fitnessplatform.mobile`. iOS local testing requires macOS/Xcode. The scheduled and manual `native-e2e.yml` workflow uses Android and macOS runners. Never report native E2E as passed without running it on an emulator or device.
