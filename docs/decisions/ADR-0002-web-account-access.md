# ADR-0002: Web personal-account access

**Status:** Accepted for the first web identity slice. **Date:** 2026-11-23.

## Context

RF-001 requires account access, while RN-001 and RN-002 require one free personal identity that can later gain contextual professional roles. The user will test the web flow before mobile access is implemented.

## Decision

Use Better Auth 1.7 with its official Drizzle adapter and PostgreSQL tables generated by its CLI. Keep Better Auth's library-owned endpoint at `/api/auth/*`; new product resources stay under `/api/v1/*`. The web form supports personal signup and email/password sign-in, and `/account` resolves identity from the server session cookie. Enable a five-attempts-per-minute sign-in limit. Never infer professional credential status from account creation. Keep the mobile app unchanged in this slice.

## Consequences

The migration creates four identity/session tables and no domain records. The current in-memory rate limit is local/single-instance only. Email verification, password recovery, shared rate-limit storage, workspaces, and professional verification require further implementation before production launch. Browser and PostgreSQL integration tests cover registration, denial, session persistence, logout, and protected-page access.
