# Testing strategy

Vitest covers pure TypeScript, web components, and API logic. Jest with React Native Testing Library covers native components. Integration tests require a disposable PostgreSQL database, supplied through `TEST_DATABASE_URL`. Browser smoke tests use Playwright in `tests/e2e/web`; native smoke tests use Maestro in `tests/e2e/mobile` on actual Android/iOS emulators. A browser test does not substitute for native coverage.

Coverage gates require at least 90% each for lines, statements, branches, and functions. Source inclusion must count untested executable files. Generated files, tests, declarations, and declarative tool configuration may be excluded. Security-critical modules added later require independent module targets and negative cases. Reports are written under root `coverage/`. Playwright now verifies personal registration, session persistence, sign-out, failed sign-in, and account protection, alongside the foundation shell and health route. Later slices add workout logging, nutrition, invitation, fork, consent/revocation, capacity, and cross-workspace denial scenarios with deterministic fixtures.

Vitest measures web, shared, database adapter, and `ui-mobile` source; Jest measures the Expo app source. The native button also has a React Native Testing Library press test. The generated Drizzle auth schema is declarative and excluded from executable coverage. Web identity tests cover form validation and error paths; credential verification and recovery remain separate work. Coverage results reflect the implemented source set, not product readiness.
